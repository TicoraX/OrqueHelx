## 1. Bugs confirmados

### B1 — Escritura fuera de `snapshots/` vía `/api/snapshot` · CRÍTICO
`ui/server.py:493` (`_guardar_snapshot`)

El nombre del board se filtra solo con `".." in limpio`. Una ruta **absoluta** no
contiene `..` y `Path.__truediv__` la deja reemplazar la base entera.

```
POST /api/snapshot {"board": "C:/Users/santi/AppData/Local/Temp/claude/PWNED", ...}
-> {"ok": true, ...}
-> C:\Users\...\Temp\claude\PWNED_1787203296.json   (ESCRITO)
```

Explotado en vivo. `sub/x` también escapa. Es la **misma clase de bug** que
`_archivo` ya arregló y que ESTADO.md documenta como decisión ("el nombre de
archivo va por lista blanca"): el arreglo no se propagó a la pieza nueva.

`_restaurar_snapshot` sí valida bien (`resolve()` + comparación de padre).

### B2 — Inyección de código en el script exportado · CRÍTICO
`ui/server.py:607` (`_generar_script_python`)

`board` se interpola sin escapar dentro de un literal de string del script generado:

```python
board = GRAFO.get("board", "x" ; import os; os.system("echo pwn") #")
```

El script se descarga y se corre a mano. Un grafo importado de un tercero ejecuta
código arbitrario en la máquina de quien lo corra.

### B3 — "Optimizar goal" y "Generar grafo con IA" no hacen nada · ALTO
`ui/server.py:205` y `ui/server.py:468`

Ambos leen `res.get("respuesta")`. `run_chat` → `chat_backend` devuelve la clave
**`texto`**. `"respuesta"` no la produce nadie en el repo (grep confirmado; la UI
lee `datos.texto` correctamente en el chat).

Consecuencias, verificadas en vivo:

```
POST /api/optimizar-goal {"goal":"revisa el repo","runtime":"claude-code"}
-> {"ok": true, "optimizado": "revisa el repo"}     # idéntico a la entrada
```

- **Optimizar**: devuelve el goal sin tocar y la UI pinta "Goal optimizado con éxito".
- **Generar grafo**: `json.loads("")` lanza, el `except` traga, y siempre sale el
  template dummy de 3 nodos (`analisis → ejecucion → sintesis`). El usuario cree
  que un agente le diseñó el flujo.

Dos features de cara al usuario están muertas y fallan **en silencio y en verde**.

### B4 — El heartbeat del claim va a la base equivocada · ALTO
`dispatcher/loop.py:118` (`ejecutar_una`)

```python
c = k.connect()          # sin board  <- aca
```

Cada board tiene su propia SQLite (`kanban_db.connect` resuelve por
`board` → env → `kanban/current` → `default`). El hilo de latido abre la base
*default*, `heartbeat_claim` no encuentra la task, devuelve `False` — y el retorno
se ignora.

La misma función acierta en `tick`: `k.connect(board=board) if board else k.connect()`.

Efecto: en cualquier board que no sea el default, `release_stale_claims` puede
sacar la card en una corrida de más de 15 minutos. Es exactamente el escenario que
el comentario de esa línea dice estar previniendo.

---

### B5 — Un cuerpo POST malformado tumba la conexión · MEDIO
`ui/server.py:897-899`

`int(Content-Length)` y `json.loads(...)` están **fuera** del `try`:

```
curl -d 'no-es-json' /api/validar        -> sin respuesta (curl exit 52)
curl -H 'Content-Length: abc' -X POST    -> sin respuesta
```

Traceback en consola, socket cerrado, cero JSON de error. Tampoco hay tope de
tamaño de cuerpo.

### B6 — El query string no se decodifica · MEDIO
`ui/server.py:846`

```python
params = dict(p.split("=", 1) for p in query.split("&") if "=" in p)
```

Sin `urllib.parse`. `_archivo` acepta espacios en el nombre, así que un grafo
llamado `mi flujo` se guarda bien y después es **inabrible**:

```
GET /api/grafo?nombre=mi%20flujo
-> {"error": "nombre de grafo invalido: 'mi%20flujo' ..."}
```

## 3. Lo que está bien

No todo es hallazgo. Vale registrarlo para no "arreglarlo" después:

- **Escapado en la UI**: los 22 `innerHTML` pasan por `esc()`, y `renderMarkdown`
  escapa **antes** de aplicar el markdown. La salida de un agente no inyecta HTML.
- **`_archivo`**: lista blanca + `resolve()` + verificación del padre. Es el
  modelo que le falta a `_guardar_snapshot`.
- **Auth del API**: argon2id, tokens de sesión hasheados, hash señuelo contra
  enumeración por timing, 404 en vez de 403.
- **`backends._correr`**: `stdin=DEVNULL` siempre, denylist de flags, sin `shell=True`.
- Los comentarios del código citan la evidencia de cada decisión. Varios bugs de
  esta lista se encontraron leyendo un comentario que prometía algo que el código
  de al lado ya no cumplía (B4 es el caso puro).
