## Fase 1 — Estados que faltan (máxima prioridad, menor esfuerzo)

Es la fase que más mueve la aguja: una interfaz se delata por estar **inerte**,
no por ser fea. Un screenshot de esta UI está bien; lo que falta aparece al
tocarla.

### 1.1 · `:focus-visible` en todo lo que recibe foco

Hoy hay **cero**. Navegar con teclado es imposible: no se ve dónde estás.
Insertá después de la regla `button:disabled` (buscá `button:disabled { opacity:.45`):

```css
  /* Un solo anillo para todo lo enfocable. `:focus-visible` y no `:focus`:
     el anillo aparece con teclado y no en cada clic del mouse. */
  button:focus-visible, input:focus-visible, select:focus-visible,
  textarea:focus-visible, .tab:focus-visible, .card-intencion:focus-visible,
  .chip-reciente:focus-visible, [tabindex]:focus-visible {
    outline: 2px solid var(--acento);
    outline-offset: 2px;
    border-radius: 4px;
  }
```

Y las tarjetas de intención y los chips de recientes hoy son `<div>` con
`onclick`: el teclado ni siquiera llega. Agregales `tabindex="0"` y
`role="button"` en el HTML (`class="card-intencion"` y `class="chip-reciente"`),
y en el JS del handler agregá el disparo por teclado:

```js
  // Un div con onclick es invisible para el teclado. Enter y Espacio son lo que
  // un boton hace de fabrica, y esto es un boton disfrazado de tarjeta.
  card.onkeydown = e => {
    if (e.key === "Enter" || e.key === " ") { e.preventDefault(); card.click(); }
  };
```

### 1.2 · `:active` — el acuse de recibo de un clic

También cero. Es el ítem que el audit de tells califica como el de mayor señal.
Al lado de `button:hover:not(:disabled)`:

```css
  /* 60ms: el receipt de un click tiene que sentirse en el pointer-down, no
     despues. Mas lento se percibe como lag, no como respuesta. */
  button:not(:disabled):active { transform: scale(.97); }
  button { transition: transform 60ms ease-out, border-color 120ms ease-out; }
  .card-intencion:active { transform: scale(.99); }
```

### 1.3 · Estado vacío del modo App

Hoy `#appTimelineNodos` y `#appEntregableRender` arrancan literalmente vacíos:
un rectángulo con borde y nada adentro, que se lee como "roto", no como
"todavía no". Poné contenido inicial en el HTML (no en JS):

- `#appTimelineNodos`: `<div class="d">Los nodos aparecen acá cuando arranca la corrida.</div>`
- `#appEntregableRender`: ya tiene un `<div class="d">` al lanzar; agregale uno
  equivalente en el HTML estático para el estado previo.

Y en `renderMarkdown`, el `return '<div class="d">Sin contenido</div>'` está
bien: no lo toques.

### 1.4 · `::selection`, `caret-color` y scrollbar

Tres propiedades que nadie mira y por eso delatan. Después del bloque `body`:

```css
  ::selection { background: color-mix(in oklab, var(--acento) 35%, transparent); }
  input, textarea { caret-color: var(--acento); }
  /* Firefox y Chromium. El panel scrollea mucho y la barra por defecto es del
     sistema, o sea de otro producto. */
  * { scrollbar-width: thin; scrollbar-color: var(--linea) transparent; }
  ::-webkit-scrollbar { width: 9px; height: 9px; }
  ::-webkit-scrollbar-thumb { background: var(--linea); border-radius: 6px; }
  ::-webkit-scrollbar-thumb:hover { background: #3b4250; }
  ::-webkit-scrollbar-track { background: transparent; }
```

## Fase 2 — Responsive

`aside { width:340px }` fijo y una sola `@media` en todo el archivo. En una
tablet el lienzo queda en ~380px de ancho y es inusable; en un monitor ancho el
panel se ve angosto al lado de un lienzo enorme.

Dos breakpoints, no cinco. Insertá al final del `<style>`:

```css
  /* Dos cortes, elegidos por lo que le pasa a ESTE layout, no por tamanos de
     dispositivo: a los 1100 el panel se come el lienzo, y abajo de 760 no hay
     lienzo utilizable y el modo App es lo unico que tiene sentido. */
  @media (max-width: 1100px) {
    aside { width: 300px; }
    #panelPlantillas { width: 280px; }
  }
  @media (max-width: 760px) {
    body { flex-direction: column; }
    aside { width: 100%; height: 45vh; border-left: none;
            border-top: 1px solid var(--linea); }
    body.modo-studio-activo #panel { height: 45vh; margin-top: 0; }
    body.modo-studio-activo #lienzo { height: calc(55vh - 44px); }
    .app-contenedor { padding: 0 4px; }
    .grid-intenciones { grid-template-columns: 1fr; }
  }
  @media (min-width: 1800px) {
    aside { width: 400px; }
  }
```

**Verificación**: abrí el Studio y achicá la ventana a 700px de ancho. El panel
tiene que quedar abajo y el lienzo arriba, sin scroll horizontal en `body`.

## Fase 3 — Dos registros de espaciado y radio único

Hoy `gap:8px` y `gap:4px` se usan las dos para separar controles *dentro* de un
grupo y para separar secciones *entre* sí. Un solo valor afirma que todo pesa
igual, y no es cierto: el panel tiene secciones con títulos.

Agregá al `:root`:

```css
    /* Dos registros. Intra: lo que vive junto adentro de un control o grupo.
       Ritmo: lo que separa secciones que se leen aparte. */
    --intra-1:4px; --intra-2:8px;
    --ritmo-1:14px; --ritmo-2:24px;
    --radio:6px;
```

Después:

1. `#panelCuerpo { ... gap:14px }` → `gap:var(--ritmo-2)`. Las secciones del
   panel son unidades distintas y hoy respiran igual que dos botones pegados.
2. `.tab-vista { gap:14px }` → `gap:var(--ritmo-1)`.
3. `.fila { gap:8px }` → `gap:var(--intra-2)`.
4. `.tabs { gap:4px }` → `gap:var(--intra-1)`.
5. Todos los `border-radius` de 5px, 8px, 9px y 10px → `var(--radio)`.
   **Excepción**: `.meta i { border-radius:9px }` es una píldora, se queda
   (`border-radius:999px` para que sea explícitamente una píldora y no un radio
   suelto), y `#panelPlantillas { border-radius:8px }` se queda en 8 porque
   flota sobre el lienzo y tiene otra jerarquía. Anotá las dos excepciones con
   un comentario de una línea.

## Fase 4 — Los 41 hex sueltos y el rol tipográfico de dato

### 4.1 · Migrar los hex de los `style=` inline

41 colores viven fuera del sistema: `#171a20`, `#232833`, `#0d1117`, `#141720`,
`#1e293b`, `#38bdf8`, `#7dd3fc`, `#fca5a5`... Mapa de migración:

| Hex suelto | Reemplazo |
|---|---|
| `#141720`, `#171a20` | `var(--hundido)` (nuevo: `--hundido:#141720`) |
| `#232833` | `var(--control)` (nuevo: `--control:#232833`) |
| `#0d1117` | `var(--sobre-acento)` (nuevo, el texto sobre `--acento`) |
| `#38bdf8`, `#7dd3fc` | `var(--acento-claro)` (nuevo: `--acento-claro:#7dd3fc`) |
| `#fca5a5`, `#e0706d` | `var(--peligro-texto)` (nuevo: `--peligro-texto:#e0706d`) |
| `#1e293b`, `#223042`, `#212c3d` | `var(--control-frio)` (nuevo: `--control-frio:#1e293b`) |

Y declarar el sesgo arriba del `:root`:

```css
  /* Neutros con sesgo FRIO deliberado (azulado, ~230deg): es una consola que se
     mira de noche al lado de una terminal, y un gris neutro puro al lado de una
     terminal azulada se ve sucio. Los seis colores de estado NO son decorativos:
     son los estados de `kanban_db.VALID_STATUSES`. */
```

Regla: si un `style=` inline tiene un color que ya existe como variable, usá la
variable. Si aparece una sola vez y es específico de ese elemento, dejalo pero
agregale un comentario de por qué es único.

### 4.2 · Rol tipográfico de dato

Agregá al `:root` y una clase:

```css
    --mono: ui-monospace, SFMono-Regular, "Cascadia Mono", Consolas, monospace;
```

```css
  /* Segundo rol tipografico: DATO. Un id de card (`t_ae2d7ec6`), un slug de
     board y un monto no son prosa, y en una sans se leen mal justo cuando hay
     que compararlos de un vistazo. La necesidad ya estaba: habia dos
     `tabular-nums` sueltos y `.res` ya usaba monoespaciada. */
  .dato { font-family: var(--mono); font-variant-numeric: tabular-nums;
          font-size: .92em; letter-spacing: -.01em; }
```

Aplicá `class="dato"` a: el id de card en la traza, el slug de board del badge
(`#txtNombreWsActual` y `#appBoardTitulo`), los montos en USD del panel de
consumo, el `#nodoImpactoBadge`, y los ids de nodo del timeline del modo App.

### 4.3 · `--failed` nombra un estado que no existe

`VALID_STATUSES` no tiene `failed`: un fallo terminal cae en `triage` o
`blocked`. La variable `--failed` sigue en uso para pintar esos dos. Renombrala
a `--bloqueado` y actualizá los usos. Es la tercera vez que ese nombre inventado
causa un bug en esta rama; que no quede ni en el CSS.

## Fase 5 — Motion (presupuesto: seis momentos, banda 60–180ms)

**Primero arreglá lo que ya anima mal**, después agregá.

### 5.1 · `transition: all` (línea ~222, `.card-intencion`)

Anima propiedades que nadie eligió, incluidas las de layout. Reemplazar por la
lista explícita:

```css
    transition: border-color 140ms ease-out, background 140ms ease-out,
                transform 60ms ease-out;
```

### 5.2 · Las tres barras que animan `width`

`#appBarraProgreso`, `#teleProgresoBarra` y la barra inline de ~línea 2568
tienen `transition:width .3s`. Animar `width` fuerza layout en cada frame.
Cambiar a `transform: scaleX()` con `transform-origin: left`:

```css
  .barra-progreso-fill {
    width: 100%; transform-origin: left; transform: scaleX(0);
    transition: transform 180ms ease-out;
  }
```

Y en el JS, donde hoy dice `style.width = pct + "%"`, poner
`style.transform = "scaleX(" + (pct/100) + ")"`.

> **Ojo**: `tests/ui_navegador.mjs` afirma `app.ancho === '50%'` leyendo
> `style.width`. Si cambiás esto, **actualizá esa aserción** para leer el
> `transform`. Correr `tests/test_ui_navegador.py` y que quede en TODO OK.

### 5.3 · Los cuatro momentos nuevos (y ninguno más)

| # | Dónde | Receta | Duración |
|---|---|---|---|
| 1 | `#aviso` al aparecer | `translateY(-4px)` + fade | 140ms |
| 2 | `#panelPlantillas.abierto` | `scale(.98)` + fade, origen top right | 140ms |
| 3 | Modal de entregable | fade del backdrop + `scale(.98)` de la caja | 180ms |
| 4 | Nodo del lienzo mientras se arrastra | `drop-shadow` que aparece al agarrar | 80ms |

Nada más. El cambio de solapa y los mensajes de chat **no se animan**: son
frecuentes, y animar lo frecuente convierte una interfaz en un peaje.

Para el #4: la clase `.arrastrando` **no existe** — se verificó, cero
ocurrencias. El lienzo redibuja el SVG entero en cada `mousemove` (`pintar()`
dentro del handler), así que no hay un elemento persistente al que engancharse.
La forma correcta es agregarla en el mismo lugar donde ya se agrega `.sel`,
`ui/index.html:907`:

```js
    g.setAttribute("class", "nodo" + (sel === n.id ? " sel" : "") +
                            (arrastre && arrastre.id === n.id ? " arrastrando" : ""));
```

```css
  .nodo.arrastrando rect { filter: drop-shadow(0 4px 10px rgba(0,0,0,.5)); }
  .nodo rect { transition: filter 80ms ease-out; }
```

`arrastre` ya es la global que lleva el nodo agarrado (`ui/index.html:740`).

Todo lo nuevo va envuelto en el `@media (prefers-reduced-motion: reduce)` que ya
existe en la línea 102 — **extendé esa regla**, no crees otra.
